# Nucleus Flow Design

## Context

После готовой диагностики в пользовательском боте уже есть кнопка `Узнать про «Ядро»`.
Отдельного сценария для этой кнопки сейчас нет.

Нужен новый flow с:

- вступительным экраном;
- дополнительными экранами `Что будет внутри` и `Как попасть`;
- сбором заявки в `Ядро`;
- подтверждением пользователю;
- уведомлением в админку.

## Decision

Заявка в админку отправляется через RabbitMQ и `admin-bot`, а не напрямую из пользовательского бота.

Это соответствует текущей архитектуре проекта:

- пользовательский бот ведёт диалог с пользователем;
- админский бот рассылает админские уведомления по списку `CHAT_IDS`;
- RabbitMQ уже используется как транспорт между сервисами.

## Target Flow

### 1. Вход в Ядро

Если пользователь нажимает `Узнать про «Ядро»`, бот:

- отправляет видео `кружок №6`;
- отправляет текст про `Ядро`;
- показывает кнопки:
  - `Что будет внутри`
  - `Как попасть`
  - `Доступ сĸоро отĸроется`
  - `Назад`

Кнопка `Доступ сĸоро отĸроется` ведёт на тот же экран, что и `Как попасть`.

### 2. Экран `Что будет внутри`

Бот отправляет текст про содержимое `Ядра` и показывает:

- `Как попасть`
- `Назад`

### 3. Экран `Как попасть`

Бот отправляет текст про запуск, условия и подписку и показывает:

- `Оставить заявĸу в «Ядро»`
- `Назад`

### 4. Экран заявки

Бот просит прислать одним текстовым сообщением:

- имя и фамилию;
- почему откликается участие;
- что сейчас особенно важно в движении к масштабу.

Показывается кнопка:

- `Назад`

### 5. После отправки заявки

Если пользователь отправляет заявку текстом, бот:

- подтверждает приём заявки;
- отправляет уведомление в админку через RabbitMQ.

В админку уходят:

- `username`;
- `имя / фамилия` из Telegram-профиля;
- текст заявки;
- дата / время.

## Technical Design

### Bot

Новый feature-модуль:

- `bot/handlers/events/nucleus/`

Внутри:

- `handlers.py`
- `buttons.py`
- `states.py`
- `publisher.py`
- `__init__.py`

Состояния:

- `intro`
- `inside`
- `how_to_join`
- `waiting_for_application`

Для `Как попасть` сохраняется предыдущий экран в FSM data, чтобы `Назад` возвращал туда, откуда пользователь пришёл.

### RabbitMQ

Добавляется новая очередь:

- `RMQ_NUCLEUS_APPLICATION_QUEUE`

Пользовательский бот публикует туда словарь с полями заявки.

### Admin Bot

В `admin-bot` добавляется новый subscriber для этой очереди.
Он форматирует сообщение и рассылает его во все `CHAT_IDS`.

## Testing

Проверка после изменений:

- `py_compile` для новых и затронутых Python-файлов;
- проверка JSON-файлов;
- ручная проверка сценария:
  - `Узнать про «Ядро»`
  - `Что будет внутри`
  - `Как попасть`
  - `Оставить заявĸу в «Ядро»`
  - отправка текста заявки
  - `Назад` на каждом шаге.
