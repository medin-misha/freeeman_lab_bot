# Analysis Booking Flow Design

## Context

В пользовательском боте уже есть вход в сценарий разбора после готовой диагностики.
Раньше этот сценарий был линейным и вёл через промежуточный шаг `Я готов к разбору!`.
Теперь нужен пошаговый flow с выбором формата разбора и отдельными экранами для:

- выбора формата;
- подтверждения заполнения анкеты;
- подтверждения записи в расписание.

На этом этапе уведомления в админку не нужны.

## Options

### Option 1: Реализовать только в `bot`

Весь новый flow строится в `bot` через тексты, callback-и и FSM-состояния.
`backend` и `admin-bot` не меняются.

Плюсы:

- минимальный объём изменений;
- нет новых API и очередей;
- меняется только пользовательский UX.

Минусы:

- факт записи на разбор не хранится в backend;
- админская часть добавится отдельной задачей.

### Option 2: Делать через `backend`

Добавить отдельную сущность или event для записи на разбор и прокинуть его в `admin-bot`.

Плюсы:

- данные будут храниться централизованно;
- проще развивать админский контур дальше.

Минусы:

- сильно больше изменений;
- не соответствует текущему объёму задачи.

## Decision

Выбран `Option 1`.

Новый flow реализуется только в пользовательском боте.
Уведомления в админку откладываются.

## Target Flow

### 1. Вход в разбор

Если пользователь нажимает `Пойти в разбор`, бот отправляет общий экран с описанием разбора и двумя форматами:

- `Публичный разбор`
- `Приватный разбор`
- `Назад`

Выбор формата делается через inline-кнопки.
Возврат назад из этого экрана возвращает пользователя в меню результата диагностики.

### 2. Публичный разбор

Если пользователь нажимает `Публичный разбор`, бот отправляет текст про открытый формат и показывает:

- inline-кнопку `Открыть анкету`;
- inline-кнопку `Форму заполнил(а)`;
- reply-кнопку `Назад`.

`Назад` возвращает к экрану выбора формата разбора.

### 3. Приватный разбор

Если пользователь нажимает `Приватный разбор`, бот отправляет текст про закрытый формат и показывает:

- inline-кнопку `Открыть анкету`;
- inline-кнопку `Форму заполнил(а)`;
- reply-кнопку `Назад`.

`Назад` возвращает к экрану выбора формата разбора.

### 4. После заполнения анкеты

Если пользователь нажимает `Форму заполнил(а)`, бот отправляет экран с инструкцией про расписание и показывает:

- inline-кнопку `Открыть расписание`;
- inline-кнопку `Я внес(ла) себя в расписание`;
- reply-кнопку `Назад`.

На этом шаге `Назад` возвращает пользователя к экрану выбранного формата разбора.

### 5. После подтверждения расписания

Если пользователь нажимает `Я внес(ла) себя в расписание`, бот отправляет подтверждение:

`Отлично.
Я получил подтверждение записи.
Если будет перенос или вопрос — напиши заранее.`

После этого сценарий считается завершённым.
Пользователю возвращается меню после диагностики.

## Technical Design

### Files

Изменения затрагивают:

- `bot/messages.json`
- `bot/handlers/events/analysis/buttons.py`
- `bot/handlers/events/analysis/handlers.py`
- `bot/handlers/events/analysis/callbacks.py`
- `bot/handlers/events/analysis/states.py`
- `bot/handlers/events/analysis/__init__.py`

### State Model

Нужны явные состояния для корректной кнопки `Назад`:

- `choosing_format`
- `public_intro`
- `private_intro`
- `public_schedule`
- `private_schedule`

Состояние используется только для навигации назад и для восстановления текущего шага.

### Callback Model

Нужны отдельные callback-ключи:

- выбор формата;
- подтверждение заполнения анкеты;
- подтверждение записи в расписание;
- inline-назад из самого первого экрана.

Формат разбора кодируется в callback, чтобы сценарий был устойчив к повторным кликам по старым сообщениям.

### Keyboard Strategy

В одном Telegram-сообщении нельзя совместить inline-кнопки и reply-клавиатуру.
Поэтому для экранов публичного и приватного разбора бот отправляет:

1. сообщение с основным текстом и inline-кнопками;
2. отдельное короткое сообщение с reply-кнопкой `Назад`.

Тот же подход используется для шага с расписанием.

## Error Handling

- Если callback пришёл без ожидаемого контекста, бот не падает и просто показывает актуальный экран заново.
- Если пользователь нажимает `Назад` вне активного flow, обработчик не перехватывает другие ветки.
- Старый сценарий `Я готов к разбору!` удаляется из активного flow.

## Testing

Репозиторий сейчас без тестов, поэтому проверка практическая:

- синтаксис Python-файлов;
- валидность `messages.json`;
- поиск мёртвых импортов и старых кнопок;
- ручная проверка переходов:
  - `Пойти в разбор`;
  - `Публичный разбор`;
  - `Приватный разбор`;
  - `Форму заполнил(а)`;
  - `Я внес(ла) себя в расписание`;
  - `Назад` на каждом шаге.
